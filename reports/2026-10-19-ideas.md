# Idea set — 2026-10-19 (`brainstorming-game-ideas`)

Prompt (Hasan): the Playgama AI Challenge leaderboard (screenshot 2026-10-19) is full of games with
a face and a joke — Deploy on Friday, GRABBA, Totally Not Rigged, This Is Fine, Flappy Meme —
"can't we make games like these, why aren't we more creative and in a gamer's head?"

## Assumptions

Profile in `game-trend-profile.md`: solo + agent, Phaser pipeline that ships a fix in a day,
budget 0, placeholder art, Playgama sandbox live, YouTube Playables rules (text-free, no
off-platform links, 13+) baked into the current game.

Reading of the evidence (estimate): a like ratio above 50 % does not come from random
portal traffic (the games with the most plays sit at 5 %); it comes from a community the game
speaks to — developers for an on-call joke — sharing the link. The leaderboard rewards
**identity + a share object + a thumbnail that tells the joke**, not mechanics.

## Why Peek & Find reads as "not creative" (honest)

1. It was built to a certification brief: text-free, 13+, no memes, no IP, no links. Those rules
   remove the cheapest creative levers the leaderboard games use (a title joke, a meme face, text).
2. Placeholder art: the thumbnail is geometric shapes. On a list where the thumbnail *is* the
   pitch, that is the first and biggest gap.
3. Hidden object is a proven, faceless genre. Without a character or a joke it is a utility.
4. No share object: nothing a player produces that a friend would open.
5. No community push yet: no post, no share-bonus run, so likes have had no source.

The engine is not the problem: it generates validated scenes, ramps difficulty to level 150,
runs twists, ads, saves and a daily chain, and ships a build in a day. What is missing is a
face and a reason to share. Both can sit on top of the engine.

### Idea: Find Me (A)

| Field | Content |
| --- | --- |
| **Core loop** | Build a small avatar (three parts, four choices each) → the game hides it in a generated crowd of look-alikes → tap it before the hearts run out → the next crowd is denser and the look-alikes closer. |
| **Why now** | The leaderboard ranks by likes and the top two have 63 % and 54 % like ratios, i.e. a community shares them (screenshot, 2026-10-19). A personal image is the strongest share object a game can hand out (estimate). |
| **Lifecycle stage** | Hidden object: steady, not rising (estimate; no retention norms found). Identity/share games on the AI leaderboard: rising, window ≥ 3 months while the challenge runs (estimate). |
| **Twist** | A muted 3-second clip: forty look-alikes pop in, one blinks, the ring lands — "that's me". The player can export their own crowd as an image: "Can you find me?". |
| **Keep vs change** | Keep the generator, the decoy system (recolor and mirror decoys are look-alikes already), hearts, stars, daily, ads. Change: the target is the player's avatar, built from layered parts (no runtime tint, variants baked per part); add the share image. |
| **Automation lever** | The generator already validates spacing, occlusion and decoy counts; the avatar parts are a frame set like a theme; difficulty = decoy similarity and crowd size on the existing ramp. |
| **Social hook** | The "Can you find me?" image (Web Share API, download fallback; hidden on YouTube where off-platform actions are not allowed) and Shorts of pop-in → blink → ring. |
| **Monetization** | Rewarded Hint and Continue as now; interstitial after 3 scenes and 120 s; no IAP (platform); meta v2: avatar parts unlocked by streaks. |
| **MVP scope** | Avatar builder, crowd mode on the Find engine, share image, 30 levels of ramp; ~2 weeks; Playgama web first, YouTube build without the share button. |
| **Not in MVP** | Friends leaderboard, avatar shop, photo import. |
| **Kill switch** | Sandbox targets first (100 plays, 5:00 average, Playgama dashboard); then like ratio against the leaderboard's top (≥ 50 % observed 2026-10-19, estimate) and share taps per session (threshold set live by `tracking-game-metrics`). |
| **Risks** | Avatar art with placeholder shapes looks poor → a "pebble person" built from the existing shape vocabulary until the art pack. Share blocked on a host → the game stays complete without it (download fallback, button hidden where not allowed). |
| **Scores** | 4 · 5 · 5 · 3 · 4 · 3 · 5 = 29/35 |

### Idea: Odd One Daily (D, smallest possible)

| Field | Content |
| --- | --- |
| **Core loop** | The existing daily chain (five scenes) ends with a result card: an emoji row per scene (hearts kept, stars), the time, "Peek & Find #day" — copied to the clipboard or shared with one tap. |
| **Why now** | Same evidence: the leaderboard pays for shares, and the game currently produces nothing shareable (screenshot, 2026-10-19). The daily chain and streak already exist. |
| **Lifecycle stage** | Share-grid pattern: mature, still works for dailies (estimate). |
| **Twist** | A text-free game whose share is a text grid; the grid shows *where* the player lost hearts, which invites "I got it in 4" replies. |
| **Keep vs change** | Keep everything; add the card and the clipboard/share action (no network). |
| **Automation lever** | Exists: fixed daily seeds per date. |
| **Social hook** | The card; one Short per day from the daily's fifth scene. |
| **Monetization** | Unchanged. |
| **MVP scope** | Card rendering, clipboard + Web Share, e2e test; ~3 days. |
| **Not in MVP** | Friend comparison, calendar of past dailies. |
| **Kill switch** | Share taps per daily completion (threshold set live); if < 5 % after two weeks of traffic, keep the card for Shorts only. |
| **Risks** | Sandbox players are strangers, so the loop needs Hasan's channel at first → the card doubles as daily Shorts material. |
| **Scores** | 5 · 5 · 4 · 3 · 3 · 3 · 5 = 28/35 |

### Idea: Find the Cat (B)

| Field | Content |
| --- | --- |
| **Core loop** | Every scene hides one cat: a tail behind a pot, an ear under a cushion; tap it; the cat hides better every level (more occlusion, smaller cues). |
| **Why now** | Every top-7 thumbnail on the leaderboard shows a character or a face; ours shows shapes (screenshot, 2026-10-19). A character is the cheapest identity. |
| **Lifecycle stage** | "Find the cat" photo puzzles are an evergreen social format (estimate); many small competitors (Competition 2). |
| **Twist** | Occlusion as the mechanic: the generator already controls `maxOcclusion`; the cue (tail, ear) is what you find, not the object. The clip: a tail twitch → tap → the cat flops out. |
| **Keep vs change** | Keep the engine, hearts, daily, themes. Change: one character set (8 hiding poses × 3 colours), cue-based placement, a catch animation. |
| **Automation lever** | Placement by the existing occlusion and spacing invariants; the pose picked by the level's ramp. |
| **Social hook** | "The cat got me at level 37" screenshots; Shorts of the reveal. |
| **Monetization** | As now; v2 meta: a cat collection per theme. |
| **MVP scope** | One cat set, cue placement, 40 levels; ~1 week after the art exists. |
| **Not in MVP** | Collection, multiple characters. |
| **Kill switch** | Sandbox targets, then D1 against our own Peek & Find numbers (live). |
| **Risks** | The art dependency (no pack yet) → commission the cat first, one character is cheaper than five themes. A crowded niche → the cue mechanic and the themes are the twist. |
| **Scores** | 5 · 5 · 4 · 3 · 2 · 3 · 5 = 27/35 |

## Recommendation

Build **A (Find Me)** as the next bet: it is the only one that gives the game a face *and* a
share object in one move, it reuses the whole engine, and the two-week scope fits the profile.
Ship **D** first only if a share object is wanted inside the current game before the share-bonus
post (three days, no art). **B** waits for an artist.
